# 01 — Discovery

Why this is worth doing. Everything here is evidence and argument, not commitment.

**Put here:** problem statements, user interview notes and synthesis, survey results,
support-ticket analysis, market requirements documents (MRD), competitive analysis, feature
brainstorms, opportunity assessments.

**Skills:** `brainstorm-features`, `mrd-draft`

**Naming:** `mrd-<slug>.md`, `research-<topic>.md`, `brainstorm-<topic>.md`,
`interviews-<segment>.md`

## Keep evidence separable from conclusions

Raw notes and the synthesis drawn from them should be distinguishable — either separate
files or clearly separate sections. Six months on, someone will want to re-read what the
user actually said without your interpretation layered on top, usually because the
conclusion is being questioned.

Mark anything unverified as `[ASSUMPTION]`. Discovery docs get cited long after the
uncertainty around them is forgotten.
