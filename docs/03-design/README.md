# 03 — Design

How it should work and feel.

**Put here:** journey maps, service blueprints, empathy maps, design critiques, flow
descriptions, UI notes, links to design files.

**Skills:** `journey-mapping`, `design-critique`

**Naming:** `journey-<persona-scenario>.md`, `critique-<screen>.md`, `flow-<name>.md`

## The prototype is the design source of truth

Documents here explain *thinking* — why a flow is shaped this way, where the current
experience breaks, what a review found. The actual interface lives in `src/pages/`.

Don't write a document that describes a screen in prose. If you want people to understand a
screen, build it and link to it: the prototype is cheaper to change and impossible to
misread. Describe intent here; let the prototype carry the specifics.

## Date your critiques

A critique is a snapshot of a screen at a moment. Without a date it's impossible to tell
whether the findings have already been fixed.
